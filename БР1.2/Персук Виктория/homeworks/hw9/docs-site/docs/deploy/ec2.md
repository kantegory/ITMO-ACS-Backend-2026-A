# Сервер Amazon EC2

Первый вариант облачного развёртывания: приложение запускается через Docker Compose на одной виртуальной машине, а Nginx принимает внешние запросы и проксирует их на api-gateway.

## Сервер

| Параметр | Значение |
|----------|----------|
| Образ | Ubuntu Server 24.04 LTS |
| Тип инстанса | `t3.small` (2 vCPU, 2 ГБ памяти) |
| Доступ | SSH по ключу, порты 22 и 80 открыты в Security Group |
| Подкачка | Файл подкачки, без которого сборка семи образов не помещается в 2 ГБ памяти |

## Порядок развёртывания

1. На сервер устанавливаются Docker и Docker Compose из официального репозитория Docker, а также Nginx.
2. Код приложения копируется с локальной машины утилитой `rsync`.
3. Приложение запускается с production-настройками, которые задаются отдельным файлом `docker-compose.prod.yml`. Он убирает публикацию портов баз данных и сервисов наружу, оставляя доступным только api-gateway на локальном интерфейсе.

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build
```

4. Nginx проксирует запросы с порта 80 на `127.0.0.1:3000`.

## Автоматическое развёртывание

Workflow GitHub Actions при push в рабочую ветку подключается к серверу по SSH с отдельным ключом, копирует обновлённый код через `rsync` и перезапускает контейнеры. Адрес сервера, пользователь и закрытый ключ хранятся в секретах репозитория `SERVER_HOST`, `SERVER_USER` и `SSH_PRIVATE_KEY`.
