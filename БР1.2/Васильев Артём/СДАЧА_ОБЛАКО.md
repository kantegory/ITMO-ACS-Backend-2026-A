## Воспроизведение и ограничения

Полный исполняемый проект с зависимостями прежних работ находится только в собственном репозитории:

```text
https://github.com/frizyyu/ITMO-ACS-Backend-2026-A
```

ZIP — пакет шести сдаваемых работ, не отдельная копия всего курса. Для повторной сборки семи сервисов нужен полный checkout репозитория: backend берётся из ДЗ6. По отдельному согласованию там изменены только три внутренних batch DTO; публичный API, проверки прав и ЛР6 сохранены.

Повторная нагрузка создаёт синтетические учётные записи и меняет HPA/ресурсный профиль; запускать только на учебном стенде. Для нового прогона необходимо выделить новый каталог RESULTS в отдельной конфигурации, чтобы не перезаписать сохранённые summary/CSV. Базовый deploy возвращает исходные ресурсы; итоговый профиль ЛР8 применяется командой:

```bash
kubectl -n job-platform patch deployment auth-user-service --type=strategic --patch-file /opt/job-platform-cloud/lab8/optimized-auth.json
```

Нагрузочный генератор работал на той же VM: это не независимый внешний WAN-бенчмарк. Выполнение коротких SLO не доказывает месячный SLA 99%, production HA, отсутствие любых утечек памяти или полный off-host DR. Публичный стенд использует HTTP и только синтетические данные; реальные пароли/персональные данные использовать нельзя. Прикладные БД, kubeconfig, `.env`, приватные ключи, токены и дампы в ZIP не включены.
