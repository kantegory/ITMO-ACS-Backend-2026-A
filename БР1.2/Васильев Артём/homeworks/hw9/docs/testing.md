# Тестирование

## Статические проверки

Из `homeworks/hw9`:

```bash
uv run --python 3.14 --with-requirements requirements.txt mkdocs build --strict
for spec in docs/contracts/openapi.yaml docs/contracts/services/*.yaml; do
  uv run --python 3.14 --with openapi-spec-validator==0.7.2 openapi-spec-validator "$spec" || exit 1
done
uv run --python 3.14 --with check-jsonschema==0.29.2 check-jsonschema \
  --schemafile https://schema.getpostman.com/json/collection/v2.1.0/collection.json \
  docs/contracts/job-platform-dz3.postman_collection.json
```

Сборка проверяет конфигурацию и локальные ссылки Markdown, OpenAPI validator —
структуру и ссылки контрактов, JSON Schema — формат Postman Collection v2.1.
Статическая валидация не проверяет доступность API, корректность серверных
ответов или актуальность контрактов относительно бизнес-логики.

## Postman: ручной E2E на отдельном тестовом стенде

1. Скачайте [коллекцию](contracts/job-platform-dz3.postman_collection.json)
   и импортируйте в Postman. Понадобится единый gateway, доступный клиенту.
2. Задайте `baseUrl` стенда с `/api/v1` без завершающего `/`. Проверьте,
   что environment-переменная с тем же именем не перекрывает collection variable.
3. Убедитесь, что отрасли и уровни опыта заполнены, и используйте только
   тестовую БД: запуск создаёт пользователей, компанию, вакансию, резюме,
   просмотры и отклик. Полного удаления этих данных в коллекции нет.
4. Выполните 23 запроса по порядку через Collection Runner: первый запрос
   генерирует уникальные email и очищает старые ID/JWT, login сохраняет токены.
   Не сохраняйте полученные токены в экспортируемый JSON.
5. Сценарий проверяет создание вакансии, поиск соискателем, резюме, избранное,
   отклик `PENDING`, смену на `INVITED`, чтение нового статуса и удаление
   избранного. Для проверки работы HTTP-ошибок нужны отдельные негативные
   сценарии: коллекция не заменяет полный набор тестов доступа.

Ожидаемый критерий — успешные assertions всей коллекции, не просто отсутствие
сетевых ошибок. При 401/403 проверьте роль, владельца, срок JWT и выполните
сценарий заново; при пустых справочниках подготовьте данные стенда.

В ДЗ9 запросы коллекции не выполняются и результат E2E не заявляется.
Для интеграционного протокола сохраняйте фактический отчёт Runner отдельно,
предварительно удалив JWT, пароли и персональные данные.
