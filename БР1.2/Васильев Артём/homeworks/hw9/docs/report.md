## Ход работы

### Документация и контракты

В `homeworks/hw9` подготовлен сайт MkDocs 1.6.1: архитектура семи сервисов, API, аутентификация, эндпоинты, запуск, тестирование и наблюдаемость. Статика включается в образ gateway. Целевые адреса: `http://147.45.196.171:30080/docs/`, Swagger — `/docs/swagger.html`, API — `/api/v1`. Путь трафика: Traefik NodePort → Ingress → gateway ClusterIP:80.

| Требование | Реализация | Проверка и ограничение |
| --- | --- | --- |
| OpenAPI | `docs/contracts/openapi.yaml` и семь `docs/contracts/services/*.yaml`, источники — ДЗ6 | Восемь спецификаций проходят нормативный валидатор; схема не доказывает полного совпадения с runtime |
| Postman | `docs/contracts/job-platform-dz3.postman_collection.json`, новая копия на основе ДЗ3 | 23 запроса, схема Collection v2.1 и Newman в CI; имя сохранено, но копия уже не побайтово равна ДЗ3 |
| MkDocs | `mkdocs.yml`, страницы `docs/` | Строгая сборка прошла в реальном CI; публикация и браузерная проверка учитываются отдельно |
| Swagger UI | `docs/swagger.html`, swagger-ui-dist 5.17.14 | Локальный YAML, Try it out отключён; UI требует CDN jsDelivr, HTTP 200 не доказывает отрисовку |

Общий OpenAPI описывает публичный API, сервисные YAML также включают внутренние операции. Это разные представления, а не обещание совпадения всех схем с runtime. Публичные DTO сохраняют snake_case aliases, пароли исключены из ответов. Внутренние plain DTO передают camelCase: профиль — `id`, `userId`, `companyId`; вакансия — `id`, `companyId`, `employerProfileId`, `isPublished`; резюме — `id`, `userId`.

Пользовательский JWT и SERVICE_TOKEN имеют разные назначения. Gateway блокирует `/api/v1/internal/...`; роль не отменяет проверку владельца. В CI через реальные TypeScript/class-transformer/routing-controllers проверены внутренние поля, публичный формат, отказ чужому владельцу 403 и отрицательный сценарий SERVICE_TOKEN. JWT, пароли и служебные токены в отчёт не сохраняются. Публичный HTTP не защищает учётные данные; Newman к VPS использует SSH-туннель.

### Postman и фикстуры

Коллекция выполняет регистрацию/вход работодателя, создание компании и профиля, чтение справочников, публикацию вакансии, регистрацию соискателя, резюме, поиск, избранное, отклик и изменение статуса. ID и JWT передаются переменными; адрес задаётся `baseUrl`.

В копии ДЗ9 исправлен выбор dictionary ID: выбираются опубликованные записи с корректным RFC UUID, а не первая запись старого seed. При отсутствии подходящей записи проверка завершается ошибкой. `docs/contracts/e2e-dictionaries.sql` аддитивно добавляет две синтетические записи через `gen_random_uuid()`; их чтение проверено через публичный API. Фикстуры подключены к ephemeral и VPS-процедурам до Newman. Старая коллекция ДЗ3 и seed ДЗ6 не переписаны, UUID-валидация не ослаблена.

`test_fixtures.py` проверяет сохранение 23 запросов и остальных assertions, выбор RFC UUID из смешанного списка и отказ при наличии только старых несовместимых записей. Это offline-проверка, не HTTP E2E.

### Команды и результаты

Из корня репозитория в CI:

```bash
DOCS_DIR='БР1.2/Васильев Артём/homeworks/hw9'
python3 "$DOCS_DIR/test_fixtures.py"
for spec in "$DOCS_DIR/docs/contracts/openapi.yaml" "$DOCS_DIR/docs/contracts/services/"*.yaml; do
  openapi-spec-validator "$spec" || exit 1
done
check-jsonschema --schemafile https://schema.getpostman.com/json/collection/v2.1.0/collection.json \
  "$DOCS_DIR/docs/contracts/job-platform-dz3.postman_collection.json"
python3 -m mkdocs build --strict --config-file "$DOCS_DIR/mkdocs.yml"
```

В workflow закреплены `openapi-spec-validator==0.7.2`, `check-jsonschema==0.29.2`. В run `45960735288` и ephemeral-части `45960975193` для `6fd1bef` прошли схемы, строгая сборка и Newman из 23 запросов до/после пересоздания Pod и проверки отката. `ci/acceptance.sh` также проверяет HTTP-доступность страниц и контрактов, 404 internal-маршрута и 401 без JWT. Это результат временного CI-кластера, не обновлённого VPS и не браузерной отрисовки Swagger.
