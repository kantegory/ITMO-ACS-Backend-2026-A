# Аутентификация и доступ

1. `POST /api/v1/auth/register` создаёт пользователя с ролью `APPLICANT` или
   `EMPLOYER`. Обязательные поля и ограничения смотрите в [OpenAPI](api.md).
2. `POST /api/v1/auth/login` принимает email и пароль. Успешный ответ содержит
   `access_token`, `token_type: Bearer` и `user`.
3. Защищённый запрос передаёт `Authorization: Bearer <access_token>`.

Токен — JWT; срок жизни задаётся `JWT_ACCESS_TOKEN_LIFETIME` (в исходном
settings по умолчанию пять минут). После истечения нужно снова войти;
refresh-token endpoint в контракте не заявлен.

| Участник | Типичные операции |
| --- | --- |
| Гость | Регистрация, вход, опубликованные вакансии и справочники |
| APPLICANT | Собственные резюме, отклики, избранное и просмотры |
| EMPLOYER | Своя компания, профиль, вакансии и статусы откликов |

Роль не отменяет проверку владельца сущности. В hw6 auth middleware отсутствие
токена возвращает 401, неверный или истёкший токен — 403; login с неверными
учётными данными возвращает 401. Общее описание ошибок в YAML не заменяет
проверку конкретной реализации.

Внутренний `SERVICE_TOKEN` не является пользовательским JWT и не должен
попадать в Postman, Swagger или публичную документацию. Не публикуйте `.env`,
выгрузки коллекций с сохранёнными JWT и дампы ответов с персональными данными.
В копии исходной коллекции есть фиксированный учебный пароль, это не секрет
сервера и не образец безопасной эксплуатации. Используйте только одноразовые
тестовые аккаунты. Публичный HTTP не защищает пароль или JWT: для реальной
работы нужен TLS либо защищённый туннель.
