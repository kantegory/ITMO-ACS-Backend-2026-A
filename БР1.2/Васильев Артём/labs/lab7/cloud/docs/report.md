## Ход работы

### Среда и доступ

Целевой VPS Nuxt1591496: `147.45.196.171`, Ubuntu 24.04.4, 3 vCPU, 5925 MiB RAM, диск 90 GiB, ext4. Тип физического носителя не установлен. Одноузловой K3s `v1.34.13+k3s1` с containerd совмещает control plane и worker. Это не Managed Kubernetes и не отказоустойчивый кластер. Docker на учебном ПК выключен; сборки выполняются в CI.

Сеть узла: `147.45.196.171/32`, маршрут через `10.0.0.1 onlink`, интерфейс `ens3`. PodCIDR узла — `10.42.0.0/24`; диапазоны кластера по умолчанию — `10.42.0.0/16` для Pod и `10.43.0.0/16` для Service.

Путь запроса: `:30080 → Traefik NodePort → Ingress → gateway ClusterIP:80 → backend ClusterIP`. В `k8s/ingress.yml` закреплены Helm chart Traefik и CRD `40.1.7+up40.1.0`; тип сервиса задаётся через `service.spec.type: NodePort`. Gateway публикует `/api/v1` и `/docs/`, но блокирует internal API. Сам gateway не является NodePort.

Новые материалы находятся в `labs/lab7/cloud`. ЛР6 и прежний мониторинг в родительском `labs/lab7` сохранены. Backend берутся из ДЗ6; минимальные исправления внутренних DTO не меняют публичные aliases и права доступа.

### Реализация и проверки

| Требование | Код / реализация | Подтверждение и граница проверки |
| --- | --- | --- |
| Полное приложение | `k8s/app.yml`, `gateway.yml`: семь Deployment/Service и gateway в `job-platform` | На VPS запущены семь backend и gateway; TCP Ready не доказывает бизнес-E2E |
| Раздельные данные | `k8s/data.yml`: PostgreSQL, семь БД/ролей, PVC 3Gi; RabbitMQ, PVC 1Gi | Данные отделены от Pod, но единственный диск остаётся точкой отказа |
| Доставка образов | Registry Deployment `Recreate` с hostPath в `kube-system`, только `127.0.0.1:5000`, SSH-туннель | Восемь образов с полным SHA; registry не публикуется наружу |
| Готовность | TCP startup/readiness/liveness, requests/limits; init-контейнер `dist/scripts/migrate.js` | Проверка порта не заменяет HTTP, БД и авторизацию |
| Ограничение привилегий | Непривилегированный UID, drop capabilities, без automount ServiceAccount token | Внутренний SERVICE_TOKEN отделён от пользовательского JWT; секреты в отчёт не включаются |
| Обновление версии | `scripts/deploy.sh`, `render.py`: свежий JSON через `kubectl create --dry-run=client`, последовательный rollout и сверка image восьми Deployment | Run `45964832958` успешен; на VPS отдельно прочитаны восемь Ready Deployment с точным SHA `2308635cae6ebcdc272367a5c218e04b7da7c09f` |

`bootstrap.sh` подготавливает кластер, registry и секреты, сохраняя существующие значения. Публичная демонстрация использует HTTP без TLS и только синтетические данные. Стратегия `maxSurge=0`, `maxUnavailable=1` ограничивает пик ресурсов ценой возможной краткой недоступности.

В run `45960735288` и ephemeral-этапах `45960975193` для `6fd1bef` прошли сборка семи backend и gateway, Newman из 23 запросов до/после пересоздания Pod, закрытый internal-маршрут, отрицательная readiness и откат. Это результат временного CI-кластера, не обновлённого VPS.

Команда `bash scripts/backup-restore-check.sh <каталог-копий>` выполняет custom `pg_dump` семи БД, восстановление в отдельные временные БД и сравнение количеств строк по таблицам. На VPS проверка прошла для всех семи БД; исходные БД и API сохранились. Это проверка логических копий и счётчиков, не полный DR: потеря диска, off-host-восстановление и совпадение содержимого каждой строки не проверены.

На VPS также подтверждены работа шести компонентов мониторинга и реальные записи Loki для 31 из 31 запускавшегося контейнера за последние 24 часа. Здоровый мониторинг и TCP-пробы не доказывают бизнес-E2E и нагрузочную устойчивость.

### Проверка обновлённого VPS

27 ноября 2026 года run `45964832958` успешно выполнил предварительную интеграцию и доставку SHA `2308635cae6ebcdc272367a5c218e04b7da7c09f` на VPS. JUnit `newman-cloud.xml`: 23 запроса, без failures/errors. SSH-проверка подтвердила тот же image у всех семи сервисов и gateway, а не только Ready старой версии.

На самом VPS затем удалён Pod auth-user-service: создан новый UID, Deployment вернулся в Ready. Readiness намеренно изменена на порт 1; rollout не прошёл за 20 секунд, после `rollout undo` восстановлены исходный порт и Ready. Повторный Newman через публичный NodePort выполнил 23 запроса без ошибок. После этого повторены dump/restore семи БД во временные базы со сравнением счётчиков строк. Архивы БД остаются в защищённом каталоге сервера и в сдаваемые материалы не включаются.

Ранее run `45963474634` остановился на временном CI-кластере из-за кратковременного HTTP empty reply до обращения к VPS. Проверка идемпотентного HTTP GET теперь ограниченно повторяет транспортные ошибки; авторизация и бизнес-проверки не ослаблены.

### Итоговая приёмка

Автоматический push в `main` после PR №12 запустил `45973038963`: предварительная интеграция и доставка на VPS прошли. На сервере повторно прочитаны восемь Ready Deployment с образом `5772fc9a2b0f0a1acccfe8322aebe5ee2699aa58`; JUnit нового релиза — 23 testcase без failures/errors. CSS/JS документации получают правильный MIME-тип; сайт и Swagger реально отрисованы браузером.

На версии `2308635` выполнены семь нагрузочных прогонов, включая soak 20 минут: 26 573 нагрузочных HTTP-запроса, нулевые HTTP/business errors и dropped iterations. HPA наблюдался 1 → 2 → 1. Метрики и анализ приведены в ДЗ10/ЛР8. Контрольная версия `5772fc9` отличается документацией/доставкой и дополнительно проверена 60-секундным baseline: 900 запросов, SLO выполнены. Это отдельный smoke, а не повтор полного soak.

После финальной доставки повторно проверены 14 запросов Grafana и реальные записи всех 32 запущенных контейнеров, включая init/завершённые. Копии БД в сдаваемый пакет не включаются. Месячный SLA и полное off-host DR не проверялись.

## Вывод

Полная одноузловая инфраструктура обновлена на VPS: подтверждены SHA восьми Deployment, бизнес-E2E, пересоздание Pod, контролируемый неуспешный rollout и откат, логическое восстановление семи БД. Нагрузочная и визуальная приёмка выполнены; ограничения одного узла и отсутствия production TLS сохранены явно.
