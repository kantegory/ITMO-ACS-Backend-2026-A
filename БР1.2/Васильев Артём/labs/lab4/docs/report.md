# Отчет по ЛР4

## Цель

Подготовить удаленный Linux-сервер, развернуть на нем Job Platform и настроить Nginx как reverse proxy для внешнего доступа.

## Исходное приложение

За основу взята ЛР3: семь Express/TypeORM-сервисов, семь отдельных PostgreSQL и общая Docker-сеть. Добавлены только компоненты, нужные для развертывания.

## Подготовка сервера

На Ubuntu 20.04 проверены и подготовлены Git, Docker Engine, Docker Compose v2, curl и Nginx. Подготовка автоматизирована скриптом `deploy/setup-server.sh`.

Сервер имеет 1,9 ГБ RAM, поэтом образы собираются последовательно. Это снижает пиковое потребление памяти.

## Docker Compose

- backend-порты привязаны только к `127.0.0.1`;
- PostgreSQL-порты не публикуются;
- секреты передаются из `.env`;
- данные PostgreSQL хранятся в named volumes;
- для каждой БД настроен `pg_isready` healthcheck.

## Nginx

Nginx публикует приложение по префиксу `/job-platform`. Reverse proxy удаляет внешний префикс и передает запрос нужному сервису. Отдельные regex-маршруты используются для откликов и просмотров, так как их URI начинается с `/vacancies`, но обрабатывается не vacancy-service.

## Ручное развертывание

1. Создан `.env` с непубличными секретами.
2. Выполнен `docker compose config --quiet`.
3. Образы собраны последовательно.
4. Контейнеры запущены в detached-режиме.
5. Во всех сервисах выполнены TypeORM-миграции.
6. Конфигурация Nginx проверена через `nginx -t` и применена через reload без остановки сервера.

## Проверка

Внешние запросы выполняются через `https://185.236.24.201/job-platform`. Проверяются статус reverse proxy, справочники и список вакансий.

## Вывод

Приложение развернуто на удаленном Ubuntu-сервере. Nginx обеспечивает единую внешнюю точку входа, а базы данных и internal API не публикуются наружу.
