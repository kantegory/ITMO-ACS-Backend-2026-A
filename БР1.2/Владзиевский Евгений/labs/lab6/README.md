# ЛР6 — Настройка системы мониторинга ресурсов

Мониторинг и наблюдаемость для микросервисного приложения, развёрнутого
в ЛР4–ЛР5: метрики виртуальной машины, healthcheck всех микросервисов и
логи всех контейнеров в одном дашборде Grafana.

## Состав стека

| Компонент | Роль |
|---|---|
| **Prometheus** | сбор и хранение метрик (retention 15 дней) |
| **node-exporter** | метрики ВМ: CPU, RAM, диск, сеть |
| **cAdvisor** | метрики по контейнерам |
| **blackbox-exporter** | опрос `/health` каждого микросервиса |
| **Loki** | хранение логов (retention 7 дней) |
| **Promtail** | сбор логов всех docker-контейнеров |
| **Grafana** | дашборд: метрики, доступность, логи |

## Структура

```
lab6/
├── monitoring/
│   ├── docker-compose.monitoring.yml
│   ├── prometheus/prometheus.yml
│   ├── blackbox/blackbox.yml
│   ├── loki/loki-config.yml
│   ├── promtail/promtail-config.yml
│   └── grafana/
│       ├── provisioning/datasources/datasources.yml
│       ├── provisioning/dashboards/dashboards.yml
│       └── dashboards/rental-overview.json
└── ansible/
    ├── monitoring.yml        # плейбук развёртывания
    └── roles/monitoring/     # роль: конфиги, .env, запуск стека
```

Роль `nginx` не дублируется — она переиспользуется из ЛР5 через
`roles_path = roles:../../lab5/ansible/roles`, ей лишь передаётся
`grafana_enabled: true`, и в конфиге прокси появляется локация `/grafana/`.

## Развёртывание

```bash
cd ansible
ansible-playbook monitoring.yml --ask-pass
```

Плейбук копирует конфигурации в `/opt/rental-monitoring`, генерирует `.env`
с паролем администратора Grafana (один раз), поднимает стек и дожидается
готовности Grafana.

## Доступ

| Что | Адрес |
|---|---|
| Grafana | http://192.168.1.245/grafana/ |
| Дашборд | Rental → «Rental App — ресурсы, доступность, логи» |
| Prometheus | только внутри docker-сети |
| Loki | только внутри docker-сети |

Наружу стек мониторинга не публикует ни одного порта: Grafana доступна
через nginx, остальные компоненты — только внутри сети контейнеров.
Пароль администратора лежит на сервере в `/opt/rental-monitoring/.env`.

## Дашборд

1. **Ресурсы ВМ** — CPU, RAM, заполнение диска и аптайм плитками; графики
   загрузки CPU по режимам, памяти, сетевого трафика и дискового I/O.
2. **Доступность микросервисов** — плитки UP/DOWN по каждому из шести
   сервисов, счётчик доступных сервисов, история доступности и время
   ответа `/health`; плюс CPU и память по контейнерам приложения.
3. **Логи контейнеров** — скорость логирования по контейнерам и панель
   логов с фильтрами по контейнеру и подстроке (переменные дашборда).
