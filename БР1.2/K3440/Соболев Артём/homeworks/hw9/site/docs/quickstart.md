# Быстрый старт

Для запросов нужен адрес запущенного шлюза FitnessAPI. В примерах `https://fitnessapi.example` обозначает этот адрес. Подставьте свой адрес вместе со схемой HTTP или HTTPS, без завершающего слеша и без `/api/v1`.

## Первый запрос

Запрос возвращает первую страницу каталога упражнений. Нумерация страниц начинается с нуля.

```bash
curl -i "https://fitnessapi.example/api/v1/exercises?page=0&size=20"
```

При успешном запросе сервер возвращает `200 OK` и JSON. Поле `content` содержит упражнения. Пустой массив означает, что на странице нет записей.

## Тот же запрос в Swagger UI

1. Откройте `/api/v1/swagger-ui/index.html` на адресе шлюза.
2. Выберите в меню `training-service`.
3. Найдите операцию `GET /exercises` и нажмите **Try it out**.
4. Укажите `page=0` и `size=20`, затем нажмите **Execute**.

Для операций со значком замка см. раздел [Авторизация](auth.md).

## Как прочитать ответ каталога

Пример ответа для пустой первой страницы:

```json
{
  "content": [],
  "page": 0,
  "size": 20,
  "numberOfElements": 0,
  "hasNext": false,
  "first": true,
  "last": true
}
```

| Поле | Что означает |
| --- | --- |
| `content` | Упражнения, которые попали на текущую страницу |
| `page` | Номер текущей страницы, начиная с нуля |
| `size` | Запрошенный размер страницы |
| `numberOfElements` | Количество записей на текущей странице |
| `hasNext` | Есть ли следующая страница |
| `first` и `last` | Является ли текущая страница первой или последней |

Если `hasNext` равно `true`, увеличьте `page` на единицу и оставьте тот же `size`. Идентификатор упражнения из `content` можно подставить в `GET /api/v1/exercises/{exerciseId}`, чтобы получить одну запись.

## Если запрос вернул ошибку

| HTTP-код | Что проверить |
| --- | --- |
| `400` | Формат параметров и тела запроса по схеме в Swagger UI |
| `401` | Наличие и срок действия токена доступа |
| `403` | Права текущей учётной записи на операцию |
| `404` | Путь, префикс `/api/v1` и идентификатор записи |
| `502` | Доступность сервиса, к которому шлюз передаёт запрос |

В ответе приложения могут быть поля `message` и `errorCode`. При ошибке проверки данных посмотрите массив `errors`, если он присутствует: в нём перечисляются ошибки отдельных полей.
