# ЛР6. Мониторинг микросервисов средствами Grafana

Стек мониторинга собирает метрики виртуальной машины в Prometheus, проверяет
доступность сервисов, отправляет Docker-логи в Loki и автоматически загружает
дашборд в Grafana.

## Состав

- **Grafana** — интерфейс и готовый дашборд;
- **Prometheus** — хранение метрик с интервалом 15 секунд;
- **node-exporter** — метрики CPU, RAM, файловых систем и сети виртуальной машины;
- **Blackbox Exporter** — HTTP-проверки `/health` всех шести сервисов и TCP-проверки PostgreSQL/RabbitMQ;
- **Promtail и Loki** — сбор и хранение логов всех Docker-контейнеров ВМ.

Дашборд содержит графики нагрузки CPU, использования RAM и диска, сетевого
трафика RX/TX, статусы сервисов и зависимостей, а также логи контейнеров.
Статус HTTP-пробы означает, что сервис ответил успешным HTTP-кодом на `/health`.

## Установка на ВМ

Сначала разверните приложение из `lab5`: мониторинг подключается к Docker-сети
приложения `fitness-platform_default` и проверяет сервисы по их именам внутри
этой сети. Если в `lab5` задавали `app_dir` с другим именем, имя сети будет
`<имя-каталога>_default`.

Скопируйте каталог `lab6` на виртуальную машину с Docker Engine и Docker Compose
Plugin (например, в `/opt/fitness-monitoring`), затем выполните:

```bash
cd /opt/fitness-monitoring
cp .env.example .env
```

Укажите в `.env` фактическое имя сети приложения и задайте уникальный длинный
пароль Grafana. Не публикуйте файл `.env`. Если приложение работает в сети с
другим именем, измените `APP_DOCKER_NETWORK`.

Запустите стек:

```bash
docker compose --env-file .env -f compose.yml up -d
docker compose --env-file .env -f compose.yml ps
```

Откройте `http://<адрес-ВМ>:3000` (или порт из `GRAFANA_PORT`). Имя пользователя
и пароль задаются в `.env`. Дашборд **Fitness platform monitoring** появится
автоматически в папке **Fitness platform**.

## Заметки по эксплуатации

- Откройте во внешнем firewall только порт Grafana и ограничьте доступ к нему
  доверенными IP-адресами. Prometheus и Loki наружу не публикуются. node-exporter
  использует сетевой namespace хоста для точного учета сетевого трафика, поэтому
  его порт 9100 должен быть закрыт для внешних адресов в firewall ВМ.
- Promtail читает Docker JSON-логи с хоста в режиме read-only; сокет Docker не
  монтируется. Для сбора логов Docker должен использовать драйвер `json-file`.
- Prometheus хранит метрики 15 дней, Loki — логи до 7 дней. Данные и позиции
  чтения сохраняются в Docker volumes.
- Проверка приложений выполняется по HTTP `/health`; PostgreSQL и RabbitMQ
  проверяются TCP-подключением к портам 5432 и 5672.
- node-exporter читает `/proc`, `/sys` и файловые системы хоста для сбора
  системных метрик.

Остановить мониторинг, не удаляя накопленные данные:

```bash
docker compose --env-file .env -f compose.yml down
```
