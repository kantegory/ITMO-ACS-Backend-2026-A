# Задача

Подготовить удалённый сервер, развернуть приложение и настроить nginx как обратный прокси.

# Ход работы

Ранний серверный прогон сохранён в прежнем PDF: в нём описан сервер 158.160.152.229 и прогон 65 запросов. Эти исторические сведения не являются проверкой текущего сервера.

24.11.2026 проведён аудит новой ВМ 38.87.117.47: Ubuntu 24.04.5, около 6 GiB RAM, 43 GiB диска. На ней уже работают FinPlan (Caddy, приложение, PostgreSQL) и VPN. Порты 80/443 заняты, поэтому выбран изолированный проект `itmo-semester2`. Системный reverse proxy и чужие контейнеры не меняются.

Подготовлен `infra/semester2/compose.yml`: восемь PostgreSQL, Kafka, Elasticsearch, десять приложений, отдельный nginx. Gateway доступен на loopback:18082, nginx — loopback:18080. Все базы используют volumes, служебные порты не публикуются. nginx проксирует запросы на api-gateway:8080, ограничивает размер тела и закрывает `/actuator` и `/internal` снаружи. Management endpoints слушают только внутри сети на 9091.

Сборка Java 17 выполняется в Docker; Gradle использует общий BuildKit cache, одного worker и in-process Kotlin compiler. Это снижает потребление памяти. Не следует запускать сборку всех десяти JVM параллельно на маломощной машине.

```bash
python scripts/semester2/init-env.py
bash scripts/semester2/compose.sh config --quiet
bash scripts/semester2/compose.sh up -d --no-build --wait --wait-timeout 600
curl -f http://127.0.0.1:18080/api/v1/industries
```

# Проверка и ограничения

Локально запустились все десять приложений. Через nginx открылись Swagger UI и девять схем OpenAPI, а защищённый management endpoint вернул HTTP 404 снаружи. Newman дважды выполнил 65 запросов с 65 успешными проверками.

На общей ВМ с одним ядром восемь PostgreSQL, Kafka и мониторинг прошли проверки. Elasticsearch не достиг готовности за время ограниченного прогона. Контейнеры gateway, auth-service и user-service стартовали, но HTTP-проверка через nginx не завершилась в отведённое время. Подробности приведены в журнале проверок. Для демонстрации полного стека извне нужен стенд с запасом ресурсов.

25.11.2026 на той же ВМ последовательно запущен сокращённый профиль из gateway, vacancy-service, его PostgreSQL, Kafka и nginx. На уже существующем Caddy зарегистрирован отдельный виртуальный хост ab.pxdkxvan.lol. Caddy получил сертификат Let's Encrypt и передаёт два GET-маршрута в nginx на 127.0.0.1:18080. Путь запроса: клиент → Caddy с TLS → nginx → gateway → vacancy-service → PostgreSQL.

Из интернета оба запроса вернули HTTP 200: /api/v1/industries (2 записи) и /api/v1/experience-levels (3 записи). POST к справочнику и /actuator/health вернули 404. Проверка действующего сайта fin.pxdkxvan.lol после перезагрузки Caddy вернула прежний HTTP 307. Конфигурация публичного хоста сохранена в infra/semester2/caddy.
