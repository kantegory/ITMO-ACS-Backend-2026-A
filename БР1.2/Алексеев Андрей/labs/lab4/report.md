# Задача

Подготовить удалённый сервер, развернуть приложение и настроить nginx как обратный прокси.

# Ход работы

Существующий результат первого семестра сохранён в прежнем PDF : в нём описан сервер 158.160.152.229 и прогон 65 запросов. Эти исторические сведения не являются проверкой текущего сервера.

24.11.2026 проведён аудит новой ВМ 38.87.117.47: Ubuntu 24.04.5, около 6 GiB RAM, 43 GiB диска. На ней уже работают FinPlan (Caddy, приложение, PostgreSQL) и VPN. Порты 80/443 заняты, поэтому выбран изолированный проект `itmo-semester2`. Системный reverse proxy и чужие контейнеры не меняются.

Подготовлен `infra/semester2/compose.yml`: восемь PostgreSQL, Kafka, Elasticsearch, десять приложений, отдельный nginx. Gateway доступен на loopback:18082, nginx — loopback:18080. Все базы используют volumes, служебные порты не публикуются. nginx проксирует запросы на api-gateway:8080, ограничивает размер тела и закрывает `/actuator` и `/internal` снаружи. Management endpoints слушают только внутри сети на 9091.

Сборка Java 17 выполняется в Docker; Gradle использует общий BuildKit cache, одного worker и in-process Kotlin compiler. Это снижает потребление памяти. Не следует запускать сборку всех десяти JVM параллельно на маломощной машине.

```bash
python scripts/semester2/init-env.py
bash scripts/semester2/compose.sh config --quiet
bash scripts/semester2/compose.sh up -d --no-build --wait --wait-timeout 600
curl -f http://127.0.0.1:18080/api/v1/industries
```

# Проверка и ограничения

Текущие результаты запуска фиксируются в `../../semester2-verification.md`. Изолированный loopback-доступ через SSH-туннель не является публикацией HTTP-приложения в интернете. Для внешней демонстрации нужен домен либо согласованный отдельный внешний порт, чтобы не менять FinPlan.
