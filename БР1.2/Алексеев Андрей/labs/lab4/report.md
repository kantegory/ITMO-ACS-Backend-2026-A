# Задача

Подготовить удалённую ВМ и обеспечить внешний HTTPS-доступ к работающему API.

# Исходные данные

ВМ на Ubuntu 24.04, публичный адрес [ab.pxdkxvan.lol](https://ab.pxdkxvan.lol/swagger-ui.html). Файл запуска — `infra/semester2/auth-compose.yml`, конфигурация обратного прокси — `infra/semester2/auth/nginx.conf`.

# Ход работы

На Ubuntu 24.04 развёрнут стенд авторизации на Docker Compose. Spring Boot auth-service обрабатывает регистрацию, вход и обновление токена. PostgreSQL хранит аккаунты и учётные данные в именованном томе. Liquibase создаёт схему при запуске. Приложение получает параметры подключения и ключ подписи через окружение. Секреты хранятся на ВМ в файле с правами 0600.

# Настройка nginx

Путь запроса: клиент → Caddy (TLS) → nginx на loopback → auth-service → PostgreSQL. Caddy обслуживает домен ab.pxdkxvan.lol. Nginx передаёт разрешённые запросы, ограничивает размер тела и частоту запросов. Управляющий порт Actuator и PostgreSQL остаются в сети приложения. Nginx публикуется только на loopback.

# Проверка результата

На ВМ полный smoke прошёл через nginx и публичный HTTPS: 200 для регистрации, входа, обновления и OpenAPI, 409 для дубликата, 401 для неверного пароля и для уже использованного refresh token. /actuator/health недоступен из интернета.

Команда для воспроизведения: `python3 scripts/semester2/auth-smoke.py https://ab.pxdkxvan.lol`. В журнале приведены реальные статусы endpoint, без токенов и паролей.

# Вывод

Контейнерное приложение авторизации доступно по HTTPS после проверки сквозного сценария. Порт базы закрыт от внешней сети.
