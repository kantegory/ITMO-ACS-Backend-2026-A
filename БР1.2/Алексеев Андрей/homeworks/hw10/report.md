# Задача

Написать сценарии и профили нагрузки ключевых endpoints, определить RPS, latency p95/p99, error rate и целевые SLO.

# Ход работы

Выбран k6 0.57.0. smoke.js выполняет GET справочников industries/experience-levels и поиск vacancies с page=1&limit=10. Каждый ответ проверяется на HTTP 200 и JSON. authenticated.js использует отдельную seeded учётную запись, выполняет login и чтение users/me с access_token. Учётные данные передаются environment variables.

| Профиль | Нагрузка | Назначение |
| --- | --- | --- |
| Smoke | 1 VU, около 50 сек, sleep 1 сек | ограниченная проверка на shared VM |
| Baseline | 5 VU, 30 сек разгон, 2 мин плато, 30 сек спад | стабильная нагрузка на отдельном стенде |
| Stress | до 25 VU, 1 мин разгон, 2 мин плато, 1 мин спад | поиск насыщения и HPA |
| Authenticated | 1 VU, 30 сек | login и защищённый профиль |

Для baseline/stress требуется ALLOW_LOAD=yes. На текущем shared сервере они автоматически не запускаются. Перед содержательными испытаниями нужна фиксированная выборка минимум 1000 вакансий и прогрев: пустой индекс не даёт репрезентативной оценки поиска.

Метрики: http_reqs/длительность даёт средний RPS; http_req_duration — latency p95/p99; http_req_failed — долю ошибок; checks подтверждает валидность ответов. Метрики группируются tags endpoint. Grafana отображает CPU/RAM, request rate, p95 и 5xx; для анализа нужно сохранять временной диапазон прогона, число VU, revision и аппаратный профиль.

SLO выбранных GET при baseline: p95 < 500 ms, p99 < 1000 ms, error rate < 1%, checks > 99%. Это пороги thresholds, а не заранее полученные результаты. Целевой RPS определяется по baseline на фиксированном стенде, без необоснованной цифры производительности.

# Проверка

| Локальный прогон | Запросы | RPS | p95 | p99 | Ошибки |
| --- | ---: | ---: | ---: | ---: | ---: |
| Smoke, 1 VU | 147 | 2,89 | 19,95 мс | 29,17 мс | 0% |
| Authenticated, 1 VU | 31 | 1,01 | 45,38 мс | 83,49 мс | 0% |

Замеры получены через nginx на локальном Docker Compose стенде. Smoke проверил 294 утверждения, authenticated — 30. RPS при одном VU и паузе 1 с отражает профиль проверки и не измеряет предельную пропускную способность. Сценарии baseline/stress готовы для отдельного облачного окружения ЛР8. Ненулевой exit code k6 при нарушении thresholds должен считаться неуспехом испытания.

# Вывод

Подготовлены воспроизводимые сценарии, три профиля нагрузки, отдельная авторизованная проверка и измеримые SLO. Производительность и автоскейлинг не заявляются без измерений.
