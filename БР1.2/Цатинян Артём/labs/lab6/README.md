# ЛР6: мониторинг приложения

Отдельный Compose-проект подключается к сети `restaurant-booking_default` приложения из ЛР5. Prometheus собирает метрики node-exporter и HTTP-проверки blackbox-exporter, Alloy отправляет логи контейнеров в Loki, Grafana загружает источники данных и дашборд автоматически.

На виртуальной машине запускать из папки с файлами этой работы: `sudo docker compose up -d`, состояние: `sudo docker compose ps`. Grafana доступна на порту 3030. При первом входе стандартные локальные учётные данные Grafana `admin` / `admin`, пароль требуется изменить при первом входе. Конфигурация предназначена для локальной учебной ВМ.

Проверки сервисов используют HTTP 200 от `/v3/api-docs`, то есть показывают доступность документации API, а не полную проверку бизнес-операций. Для логов Alloy обращается к Docker API через сокет; доступ к нему даёт значительные права на Docker-хост, поэтому использовать только на доверенном локальном стенде.

На учебной виртуальной машине проверены метрики, доступность сервисов, журналы и уведомления об отказе и восстановлении. Правило Grafana хранится в provisioning/alerting; почтовая конфигурация включается файлом docker-compose.smtp.yml и локальным .env по образцу .env.example. Пароль приложения хранится только в .env. Адрес получателя и политика уведомлений настроены через Grafana и сохраняются в её томе; на новом стенде их необходимо создать заново.

Self-hosted Sentry 26.10.1 запущен отдельно в профиле errors-only; приём тестового исключения identity-service проверен. Переменная SENTRY_DSN задаётся локально и не сохраняется в репозитории. Диагностический endpoint включается только при APP_SENTRY_DEMO_ENABLED=true, по умолчанию выключен.
