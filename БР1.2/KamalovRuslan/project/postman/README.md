# Postman: комплексный сценарий FitFlow

1. Запустить локальное приложение и PostgreSQL.
2. Убедиться, что существует администратор `admin@fitflow.local` с паролем `AdminPass123`, либо изменить значения в environment.
3. Импортировать collection и environment, выбрать `FitFlow Local`.
4. Проверить `apiBaseUrl` (`http://localhost:3000/api/v1` при прямом запуске монолита, `http://localhost:8080/api/v1` через Compose) и `healthUrl` (тот же адрес без `/api/v1`). Запустить коллекцию целиком в Collection Runner строго по порядку.

В GitHub Actions обе версии проверяются через Nginx на порту 8080 с временными учебными данными. Для сервера значения URL и пароля администратора передаются отдельно при запуске; настоящий пароль нельзя сохранять в публикуемом environment. Health шлюза проверяет доступность Nginx, остальные запросы проверяют сервисы.

Сценарий генерирует уникальные email и slug, проверяет JWT и RBAC, создаёт тренировку, план, запись прогресса и статью, проверяет агрегаты и публичное чтение, затем удаляет созданные сущности. Для повторного запуска очистить значения `userEmail` и `articleSlug` в environment.
