## Цель

Я подготовил развёртывание контейнерного приложения FitFlow на Linux-сервере с Nginx.

## Текущее состояние и план проверки

Я подготовил Linux-сервер с Docker, рабочим каталогом `/opt/fitflow` и `.env` со случайными секретами и правами 0600. Успешное развёртывание самого приложения пока не подтверждено. Следующий шаг — разместить исходники, выбрать профиль и запустить контейнеры. По конфигурации Nginx маршрутизирует HTTP к внутренним сервисам, порты БД и RabbitMQ наружу не публикуются. После запуска необходимо проверить HTTP-сценарий, health-check, логи и перезапуск.

```text
cd /opt/fitflow
docker compose --profile microservices -f docker-compose.yml up -d --build
docker compose --profile microservices ps
docker compose --profile microservices logs --tail=100
```

Подробные команды первичной настройки, требования к firewall, переменным окружения, резервному копированию и TLS приведены в `deploy/server-setup.md`. Скрипт `deploy/remote-deploy.sh` проверяет наличие `.env`, валидирует Compose, собирает и обновляет сервисы без удаления томов.

## Вывод

Сервер подготовлен, но контейнерный deploy и внешний HTTP-сценарий ещё необходимо подтвердить. После проверки я добавлю фактический результат и скриншоты без секретов; приватные ключи и production .env в репозиторий не включаются.
