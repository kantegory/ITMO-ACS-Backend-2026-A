# Инструкция по серверу FitFlow

Приложение запускается локально или на одном Linux-сервере через Docker Compose. Все действия ниже ручные: наличие этих файлов само по себе ничего не публикует и не разворачивает.

## Первичная подготовка

1. Выбрать пользователя для деплоя. Для текущего учебного сервера используется `root` с отдельным SSH-ключом; такой ключ даёт полный административный доступ. Альтернатива — отдельный пользователь, при этом членство в группе `docker` также даёт привилегии уровня root.
2. Установить Docker Engine и плагин Docker Compose из официального репозитория Docker.
3. Создать `/opt/fitflow`, владельцем назначить пользователя деплоя.
4. Разрешить входящий трафик только для SSH и выбранных HTTP/HTTPS-портов. PostgreSQL и RabbitMQ наружу в Compose не опубликованы.
5. Скопировать проект в `/opt/fitflow` и создать `/opt/fitflow/.env` по примеру `deploy/.env.example`.
6. Сгенерировать разные случайные значения для `POSTGRES_PASSWORD`, `RABBITMQ_PASSWORD` и `JWT_SECRET`; выставить файлу `.env` права `0600`.

Проверка конфигурации без запуска контейнеров:

```sh
docker compose --profile microservices config --quiet
```

Запуск микросервисной конфигурации:

```sh
./deploy/remote-deploy.sh
```

Для лабораторной с монолитом используется `docker compose --profile monolith up --build -d`. Не включайте оба профиля одновременно: оба шлюза занимают один HTTP-порт.

## Эксплуатация

Статус и журналы проверяются командами `docker compose --profile microservices ps` и `docker compose logs --tail=200 SERVICE`. Перед обновлением нужно сохранить резервную копию каждого именованного тома PostgreSQL. Команда `docker compose --profile microservices down` останавливает контейнеры без удаления данных; флаг `--volumes` нельзя добавлять, если удаление баз данных не запланировано явно.

Приложенная конфигурация Nginx поддерживает только HTTP. Перед публикацией в интернете нужно настроить TLS на внешнем reverse proxy либо добавить HTTPS virtual host и автоматическое обновление сертификата.

## GitHub Actions

В environment `production` нужно добавить Secrets: `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_PATH`, `SSH_PRIVATE_KEY`, `SSH_KNOWN_HOSTS`. Приватный ключ нельзя коммитить. Ключ сервера в `SSH_KNOWN_HOSTS` следует проверить через независимую консоль провайдера.

Deploy запускается при push в `main` или вручную. Сначала выполняется переиспользуемый CI workflow; задание deploy зависит от его успешного завершения. На сервере образы собираются последовательно, затем Compose ожидает готовности контейнеров и выполняется HTTP-проверка каталога через Nginx. Автоматический rollback не реализован.
