## Цель

Я подготовил CI/CD-процесс автоматической проверки и развёртывания FitFlow.

## Pipeline

Я настроил `CI` для pull request, ручного запуска и вызова другим workflow. Pipeline устанавливает зависимости, проверяет TypeScript и тесты, запускает оба Compose-профиля, Newman и проверку проекции RabbitMQ на GitHub runner. `Deploy` при push в main сначала вызывает verify, затем копирует релиз по SSH и выполняет `deploy/remote-deploy.sh`. Серверные реквизиты задаются через GitHub Secrets; успешный runtime этих шагов ещё требуется подтвердить.

Я подготовил workflow и локальные проверки. Linux-сервер подготовлен: установлен Docker, рабочий каталог приложения — `/opt/fitflow`. Успешное развёртывание приложения и успешный полный запуск GitHub Actions пока не подтверждены. Deploy запускается при push в main и вызывает проверку verify перед развёртыванием; название workflow не делает его исключительно ручным.

## Вывод

Я разделил конфигурации проверки и развёртывания. Для завершения работы необходимо настроить secrets и подтвердить запуск pipeline и работоспособность приложения на сервере; наличие workflow само по себе этого не доказывает.
