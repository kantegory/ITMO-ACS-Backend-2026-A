# ЛР6 Мониторинг микросервисов на it-garage

Сервер: `31.77.133.132`, Ubuntu, приложение в `/opt/lab4`.
Мониторинг размещён отдельно в `/opt/lab6-monitoring` и не входит в каталог,
который обновляет GitHub Actions из ДЗ6.

## Что настроено

- Grafana — дашборд ресурсов ВМ, статусы шести микросервисов, история и логи.
- Prometheus — метрики, интервал сбора 15 секунд, хранение до 7 дней / 2 ГБ.
- Node Exporter — метрики самой ВМ, включая её настоящие сетевые интерфейсы.
- Blackbox Exporter — HTTP `/health` каждого сервиса: ожидаются HTTP 200 и
  JSON с `status: ok`. Отдельно проверяется Nginx/Gateway по публичному IP.
- Loki — логи контейнеров, срок хранения 72 часа (удаление асинхронное).
- Grafana Alloy — обнаружение всех работающих контейнеров и чтение их
  настоящих stdout/stderr через Docker API.

Все новые опубликованные порты привязаны к `127.0.0.1`. Node Exporter слушает
только внутренний адрес Docker bridge. Микросервисы не публикуются наружу.

## Как открыть Grafana

На локлаьной машине выполнить и оставить терминал работающим:

```bash
ssh -i ~/.ssh/it_garage -o IdentitiesOnly=yes -o ExitOnForwardFailure=yes -N -L 127.0.0.1:13000:127.0.0.1:3000 root@31.77.133.132
```

Открыть `http://localhost:13000/d/lab6-it-garage`.
Логин — `admin`. Случайный пароль хранится только на сервере.
Чтобы скопировать его в буфер обмена MacBook без печати в терминале:

```bash
ssh -i ~/.ssh/it_garage -o IdentitiesOnly=yes root@31.77.133.132 'cat /opt/lab6-monitoring/secrets/grafana_admin_password' | pbcopy
```

Вставить пароль в форму входа.

## Файлы

- `compose.yml` — шесть контейнеров мониторинга, сети, тома и лимиты памяти.
- `prometheus/prometheus.yml` — источники метрик и HTTP-проверки.
- `blackbox/blackbox.yml` — условия успешного ответа `/health`.
- `alloy/config.alloy` — чтение Docker-логов и их метки.
- `loki/loki.yml` — локальное хранение логов и retention.
- `grafana/dashboards/it-garage.json` — готовый дашборд.
- `grafana/provisioning/` — источники данных, дашборд и alerting.
- `scripts/prepare.py` — однократное создание случайного пароля на сервере.
- `scripts/check.py` — обычные HTTP-проверки метрик, healthcheck и логов.
- `scripts/build-dashboard.py` — исходное описание для генерации JSON.

Alloy имеет доступ к Docker socket; это привилегированный доступ к Docker API.
Socket передан только сборщику логов. Суффикс `:ro` у монтирования сам по себе
не ограничивает API исключительно операциями чтения.

## Запуск на подготовленном сервере

Требуются Docker Compose, Python 3 и работающее приложение с сетью
`lab4_default`. Из каталога `/opt/lab6-monitoring`:

```bash
python3 scripts/prepare.py --alert-email your-address@example.com
docker compose config -q
docker compose pull
docker compose up -d
docker compose ps
```

После запуска дождаться готовности компонентов (обычно около минуты), затем:

```bash
python3 scripts/check.py
```

В первом запуске заменить пример адреса на настоящий адрес получателя.
`prepare.py` не меняет существующие секреты и существующий `.env`.
При переносе на другой сервер изменить адрес публичной
проверки в конфигурации Prometheus и убедиться в совпадении имён сервисов.

## Демонстрация остановки микросервиса

На сервере из каталога приложения:

```bash
cd /opt/lab4
docker compose stop menu-service
```

Открыть дашборд: индикатор `menu-service` станет красным в течение следующего
сбора метрик и обновления страницы. Правило alerting проверяется каждые
20 секунд; после 60 секунд устойчивого отказа переходит в Alerting/Firing.

Восстановить сервис:

```bash
docker compose start menu-service
```

Индикатор снова станет зелёным. Красный участок останется в истории за
выбранный период. Для демонстрации использовать `stop`, чтобы политика
перезапуска не восстанавливала процесс сразу после принудительного `kill`.

## Почтовое уведомление

Адрес получателя задаётся параметром `ALERT_EMAIL` в закрытом `.env` на сервере.
Используется настоящий Gmail SMTP с обязательным STARTTLS и проверкой
сертификата. Пароль приложения хранится только в `secrets/smtp_password`
(UID 472, режим 0400) и передаётся Grafana через Docker secret.
Рабочая отправка включена серверным `SMTP_ENABLED=true`. Исходный
`.env.example` оставляет SMTP выключенным до ввода собственных реквизитов.

Для первоначальной настройки или замены Gmail-пароля подготовлен скрытый ввод.
Сам пароль приложения
создаётся пользователем в аккаунте Google, где должна быть включена
двухэтапная аутентификация. Затем в SSH-терминале сервера:

```bash
python3 /opt/lab6-monitoring/scripts/configure-gmail.py
```

По умолчанию отправителем будет Gmail из `ALERT_EMAIL` в серверном `.env`.
Скрипт проверяет TLS и вход в Gmail, после успеха сохраняет секрет и параметры
отправителя. Он не меняет флаг `SMTP_ENABLED` и не отправляет письмо.
В серверном `.env` должны быть заданы `SMTP_ENABLED=true`,
`SMTP_HOST=smtp.gmail.com:587`, `SMTP_USER` и `SMTP_FROM_ADDRESS`.
Для применения новых переменных и файла секрета пересоздать Grafana:

```bash
docker compose up -d --force-recreate grafana
```

После настройки выполнить Test в contact point и проверить получение письма,
а затем настоящий цикл отказа/восстановления. Настроены уведомления как о
недоступности, так и о восстановлении. Ожидание перед первым письмом — 10 секунд,
повторное напоминание о той же проблеме — через 4 часа.
Проверка правила выполняется каждые 20 секунд, длительность устойчивого отказа
до Alerting — 60 секунд; доставка письма занимает дополнительное время.
Темы писем начинаются с `[it-garage LR6]`, далее указаны `firing` или `resolved`
и имя сервиса. Временное отключение доставки из первоначальной настройки снято.

## Как пользоваться логами

В верхней части дашборда выбрать контейнер и при необходимости текст поиска.
Период задаётся справа сверху. Отображаются реальные stdout/stderr.
У тихого контейнера может не быть строк в выбранном периоде. Старые сообщения
за пределами retention не восстанавливаются. Новые контейнеры обнаруживаются
автоматически, позиции чтения Alloy сохраняются в отдельном томе.

## Обслуживание

На сервере из `/opt/lab6-monitoring`:

```bash
docker compose ps
docker compose logs --tail 50 alloy
docker compose logs --tail 50 loki
python3 scripts/check.py
docker compose restart grafana
```

Версии образов закреплены в Compose. Обновлять их осознанно с проверкой
конфигураций. Для остановки мониторинга использовать `docker compose stop`.
Тома содержат настройки Grafana, метрики, логи и позиции чтения. Не выполнять
`down -v`, если эти данные необходимо сохранить.
