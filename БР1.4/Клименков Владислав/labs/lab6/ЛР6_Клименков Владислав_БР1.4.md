## Задача

Настроить мониторинг микросервисов RecipeHub средствами Grafana и реализовать дашборд, покрывающий три обязательных сценария:

1. общее потребление ресурсов ВМ — CPU, RAM, диск, сеть;
2. healthcheck всех микросервисов;
3. просмотр логов со всех контейнеров на ВМ.

К началу работы приложение уже было развёрнуто на VPS, а инфраструктура описана через Ansible в `deploy/`. Поэтому требовалось не поднять Grafana вручную, а встроить мониторинг в существующий декларативный деплой.

## Ход работы

Мониторинг добавлен в тот же compose-проект, что и приложение. Использованы семь контейнеров: Grafana, Prometheus, Loki, Promtail, node-exporter, cAdvisor и blackbox-exporter.

Метрики собираются через Prometheus по pull-модели: node-exporter отдаёт ресурсы ВМ, cAdvisor — ресурсы контейнеров, blackbox-exporter — доступность сервисов через `probe_success`. Логи собираются цепочкой Promtail → Loki, после чего Grafana визуализирует оба источника данных. Источники и дашборд подключены через provisioning из git, а не настроены вручную через UI.

Ключевые архитектурные решения:

- все порты мониторинга привязаны к `127.0.0.1`, наружу по-прежнему смотрит только nginx; доступ к Grafana — через SSH-туннель на `127.0.0.1:3300`;
- node-exporter, cAdvisor, Prometheus и Grafana запущены в `network_mode: host`, но каждый слушает явный `127.0.0.1`, а не `0.0.0.0`;
- Loki, Promtail и blackbox-exporter оставлены в bridge-сети приложения, потому что им нужен DNS docker-сети;
- каждому контейнеру мониторинга задан `mem_limit`, чтобы при нехватке памяти OOM-killer не затрагивал приложение.

Дашборд `RecipeHub — мониторинг` содержит 27 панелей. Покрытие требований:

- **ресурсы ВМ:** загрузка CPU, RAM, диска `/`, load average, CPU по ядрам, RAM и swap, сеть, дисковый I/O, заполнение ФС, iowait/steal/system;
- **healthcheck:** 9 проверок — 3 HTTP-health сервисов, проверка через nginx и 5 TCP-проверок для PostgreSQL, RabbitMQ, Loki и blackbox; общий индикатор «ВСЕ ДОСТУПНЫ / ЕСТЬ ПРОБЛЕМЫ», плитки по сервисам, таблица и график истории;
- **логи:** объём логов по контейнерам, поток логов с фильтром по `$container` и отдельная панель только с ошибками.

Promtail использует `docker_sd_configs`, поэтому новые контейнеры подхватываются автоматически без ручного перечисления. Для «All» в переменной контейнера задано `allValue: ".+"`, иначе Loki отклоняет запрос с пустым матчером.

Мониторинг встроен в Ansible-деплой: в `compose_flags` добавлен третий compose-файл, `.env` для Grafana создаётся из шаблона с `force: false`, после деплоя проверяется health-API Grafana. Для применения правок конфигов Ansible считает хеш содержимого файлов и при изменении выполняет `--force-recreate`, потому что `docker compose up -d` не пересоздаёт контейнер при изменении только содержимого bind-mount.

## Вывод

В ходе работы настроен полноценный мониторинг микросервисного приложения: ресурсы ВМ, healthcheck сервисов и инфраструктурных зависимостей, а также централизованный сбор логов со всех контейнеров. Мониторинг встроен в существующий Ansible-деплой и не потребовал изменения CI: пуш в `main` раскатывает и приложение, и мониторинг. Дашборд версионируется в git и воспроизводится на новом сервере через provisioning. Безопасность сохранена: все порты мониторинга доступны только на loopback. Решение отлажено на реальной системе.
