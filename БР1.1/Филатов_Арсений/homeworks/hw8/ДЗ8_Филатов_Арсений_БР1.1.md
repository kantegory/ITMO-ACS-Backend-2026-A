## 1. Цель работы

Автоматизировать сборку образов микросервисов и доставку в Kubernetes-кластер kind `lab2` (целевая инфраструктура из ДЗ7/ЛР7).

## 2. Отличие от ДЗ6

В ДЗ6 деплой шёл по SSH и `docker compose up --build` на ВМ. Здесь собирается образ с тегом commit и применяется в kind через `kubectl`. Откат: `kubectl rollout undo`.

Workflow Compose (ДЗ6) не трогали: `.github/workflows/deploy-lab2.yml`.

## 3. Пайплайн

Файлы:

- `.github/workflows/deploy-lab2-k8s.yml` — build → kind load → set image → rollout status;
- `.github/workflows/rollback-lab2-k8s.yml` — ручной откат одного сервиса.

Триггер деплоя: `push` в `main` по `БР1.1/Филатов_Арсений/labs/lab2/**` или `workflow_dispatch`.

Шаги на каждый сервис (matrix: auth, catalog, jobseeker, employer, application, gateway):

1. `docker build --target <svc> -t lab2/<svc>:$GITHUB_SHA`
2. `kind load docker-image ... --name lab2`
3. `kubectl -n lab2 set image deploy/<svc> <svc>=lab2/<svc>:$GITHUB_SHA`
4. `kubectl -n lab2 rollout status deploy/<svc> --timeout=180s`

Откат: Actions → Rollback lab2 K8s → выбрать сервис → `rollout undo` + `rollout status`.

Локальный аналог без GitHub: `labs/lab2/scripts/k8s-deploy-images.ps1`.

## 4. Self-hosted runner

Runner с label `lab2-kind` на машине с Docker Desktop, kind и kubectl (кластер `lab2` из ЛР7).

1. Репозиторий → Settings → Actions → Runners → New self-hosted runner.
2. Добавить label `lab2-kind`.
3. Установить и запустить runner; в PATH должны быть `docker`, `kind`, `kubectl`.

Без runner job остаётся в Pending.

## 5. Проверка

После успешного run:

```powershell
kubectl -n lab2 get pods
kubectl -n lab2 get deploy -o wide
curl http://localhost:8080/health
```

Ожидается `{"ok":true}` и поды Running с образом на теге commit sha.

## 6. Вывод

CI/CD для kind: версионированные образы, деплой через kubectl, отдельный workflow отката. Код в `.github/workflows/` и `labs/lab2`; в `homeworks/hw8` только отчёт.
