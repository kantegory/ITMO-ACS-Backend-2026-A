## 1. Цель работы

Автоматизировать развёртывание микросервисного приложения lab2 на сервере Ubuntu одним playbook Ansible.

## 2. Playbook

Файлы лежат в `labs/lab5/ansible`. В `inventory/hosts.yml` указывают адрес ВМ и пользователя SSH. Playbook `deploy.yml` подключается к этому хосту и выполняет две роли.

Роль `docker` ставит Docker Engine и плагин Compose и включает службу `docker`. Роль `lab2` клонирует репозиторий в `/opt/itmo-acs`, записывает `.env` с секретами приложения и запускает `docker compose up -d --build` в каталоге `lab2`. Playbook дожидается ответа `GET /health` у gateway на порту 3000.

Секреты по умолчанию совпадают с локальным compose. Свои значения передаются при запуске и на сервер попадают только в `.env`, этот файл в git не коммитится.

## 3. Запуск

На машине, с которой есть SSH до сервера, нужен Ansible. В `inventory/hosts.yml` вместо `203.0.113.10` ставится адрес ВМ.

```text
cd labs/lab5/ansible
ansible-playbook -i inventory/hosts.yml deploy.yml
```

Свои секреты:

```text
ansible-playbook -i inventory/hosts.yml deploy.yml -e jwt_secret=... -e internal_secret=...
```

Если пользователь SSH не root, а входит через sudo, playbook запускают с ключом `-K`.

Повторный запуск обновляет уже склонированный репозиторий и поднимает те же контейнеры.

## 4. Выводы

Один playbook приводит сервер к тому же состоянию, что ручной запуск `docker compose up -d --build`: Docker установлен, репозиторий склонирован, контейнеры приложения работают.
