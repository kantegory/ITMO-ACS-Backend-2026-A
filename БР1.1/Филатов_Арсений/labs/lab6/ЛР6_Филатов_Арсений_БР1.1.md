## 1. Цель работы

Настроить мониторинг микросервисного приложения средствами Grafana: потребление CPU, диска, RAM и сети на виртуальной машине, доступность сервисов и просмотр логов контейнеров.

## 2. Развёртывание

Мониторинг лежит отдельно в `labs/lab2/monitoring` и поднимается вторым, в сети `lab2_default`.

```text
docker compose up -d --build
docker compose -f monitoring/docker-compose.yml up -d
```

Grafana доступна по адресу `http://<IP>:3030` (логин `admin`, пароль `admin`). Дашборд «мониторинг» находится в папке Lab6. Порт 3000 занят gateway.

Связка: node_exporter снимает метрики ВМ, Prometheus их хранит (24 часа), blackbox_exporter проверяет сервисы, Promtail собирает логи контейнеров в Loki, Grafana показывает дашборд. У gateway, auth, catalog, jobseeker, employer и application есть `GET /health`.

## 3. Дашборд

- CPU, RAM, диск и сеть виртуальной машины. Источник node_exporter.
- Доступность сервисов. HTTP `GET /health` у шести сервисов приложения, TCP у PostgreSQL (5432) и RabbitMQ (5672).
- Логи всех контейнеров на ВМ. Promtail читает stdout Docker и пишет в Loki, на дашборде есть фильтр по контейнеру.

## 4. Выводы

Мониторинг вынесен из compose приложения и не мешает автодеплою. Один дашборд закрывает ресурсы ВМ, доступность сервисов и логи контейнеров.
