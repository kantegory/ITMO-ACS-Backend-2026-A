# Коллекция Postman и автоматическая проверка Newman

Для интерактивной проверки API и сквозного регрессионного тестирования подготовлена структурированная коллекция Postman и два файла окружений:

- Коллекция: `homeworks/hw9/postman/rental-platform.postman_collection.json` (63 запроса, 129 проверок, 6 тематических папок).
- Локальное окружение: `homeworks/hw9/postman/local.postman_environment.json`.
- Облачное окружение: `homeworks/hw9/postman/upcloud.postman_environment.json`.

## Структура коллекции

1. **01. Health & Auth** — проверка `/health`, регистрация арендодателей и арендаторов, негативные кейсы (`409` дубль, `400` короткий пароль/невалидный JSON, `401` неверный пароль), логин и автосохранение JWT-токенов в переменные коллекции.
2. **02. Users** — чтение и обновление профиля (`GET/PATCH /users/me`), проверка `401` без токена.
3. **03. References & Properties** — справочники, создание/обновление/удаление объявлений, добавление фотографий, права доступа (`403`), поиск с фильтрами по городу/цене/удобствам и сортировке.
4. **04. Rentals** — оформление аренды, проверка `is_available = false`, защита от двойного бронирования (`409`), неизменность снапшота при редактировании объявления, проверки прав на завершение/отмену (`403`).
5. **05. Messages & Async Events** — переписка участников, проверка появления системных сообщений (`rental.created`, `rental.completed`) после доставки через Outbox → RabbitMQ, проверка `403` для постороннего пользователя, завершение/отмена сделок, повторная аренда и списки `/users/me/rentals`.
6. **06. Security & Cleanup** — проверка сокрытия `/api/v1/internal/*` через `api-gateway` (`404`) и очистка тестового объекта.

## Запуск через Newman

```bash
# Против облачного HTTPS-балансировщика UpCloud (с файлом окружения):
npx --yes newman@6 run "БР1.1/Зотеев Максим/homeworks/hw9/postman/rental-platform.postman_collection.json" \
  -e "БР1.1/Зотеев Максим/homeworks/hw9/postman/upcloud.postman_environment.json"
```
