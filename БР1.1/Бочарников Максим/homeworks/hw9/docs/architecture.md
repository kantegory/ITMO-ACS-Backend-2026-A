# Архитектура

| Компонент | Ответственность | Интерфейс |
|---|---|---|
| Frontend | React-приложение за nginx | HTTP, порт контейнера 80, прокси `/api/` в gateway |
| Gateway | Вход, пользователи, пакеты, задания, справочники, экспорт | FastAPI `/api/v1`, `GET /health`, SSE `/api/v1/jobs/{job_id}/events` |
| Classification worker | Разбор загруженной таблицы и постановка задания классификации | `GET /health` (порт 8001), RabbitMQ |
| File worker | Подготовка XLSX/ZIP, работа с S3, синхронизация справочника | `GET /health` (порт 8003), RabbitMQ |
| Scheduler | Повтор зависших заданий, снимок категорий, очистка загрузок | `GET /health` (порт 8002), PostgreSQL, Redis |
| ML service (4 реплики) | Классификация позиций, поиск в Qdrant | Потребитель очередей RabbitMQ, HTTP не публикует |
| Embedding и классификатор | Векторизация и модель классификации на GPU | Внутренний HTTP, `GET /health` |
| PostgreSQL, Redis, Qdrant, S3 | Состояние заданий, кэш и блокировки, векторный индекс, файлы | Внутренняя сеть `ML_net` |

Пользователь загружает Excel через `POST /api/v1/files/upload`. Gateway проверяет размер (до 10 MiB) и число строк, сохраняет файл в S3 и создаёт задание. Очередь `app.parse_table` передаёт его на разбор, затем задание уходит в `app.ml_classify`, где его берёт одна из реплик ml-service. Результат приходит в `app.ml_classify_done`, статус задания обновляется в PostgreSQL. Браузер следит за ходом по SSE `GET /api/v1/jobs/{job_id}/events`. После проверки оператор утверждает пакет, а `POST /api/v1/files/{package_id}/generate` готовит выгрузку, которую `GET /api/v1/files/{package_id}/download` отдаёт из S3.

Scheduler использует аренду заданий (lease) и перезапускает задания, которые застряли на этапе. Правка пакета защищается блокировкой (`/api/v1/locks/`). Ключи S3, JWT и адреса зависимостей принадлежат окружению.
