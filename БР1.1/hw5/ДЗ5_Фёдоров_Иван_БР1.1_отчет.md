# ДЗ5. Реализация межсервисного взаимодействия через RabbitMQ

## ЗАДАЧА

Подключить RabbitMQ к микросервисам RentEase и реализовать межсервисное
взаимодействие посредством очереди сообщений.

## ХОД РАБОТЫ

В качестве брокера выбран RabbitMQ, потому что он позволяет наглядно показать
publisher, exchange, routing key, queue и consumer без отдельного кластера.

В проект добавлены зависимости Spring AMQP в `booking-service` и
`communication-service`. В каталоге `hw5` создан Docker Compose файл с
RabbitMQ `3.13-management`, портом AMQP `5672` и Management UI на `15672`.

После подтверждения бронирования `BookingController` публикует JSON-событие
`BookingConfirmed` в direct exchange `rentease.events` с routing key
`booking.confirmed`. RabbitMQ направляет сообщение в durable queue
`communication.booking-confirmed`.

`MessageController` в `communication-service` принимает событие через
`@RabbitListener`, сохраняет два уведомления: арендатору и владельцу объекта.
Уведомления доступны через `GET /api/v1/notifications`. Для защиты от
повторной доставки используется уникальная пара `booking_id` и `recipient_id`.

Основной сценарий:

1. Клиент подтверждает бронирование.
2. Booking Service сохраняет новый статус.
3. Booking Service отправляет `BookingConfirmed` в RabbitMQ.
4. Communication Service читает сообщение из очереди.
5. Communication Service сохраняет уведомления.
6. Клиент получает уведомления через API.

Скриншоты для отчета:

- вставить скрин `docker compose up -d` и запущенного контейнера RabbitMQ;
- вставить скрин RabbitMQ Management UI с exchange `rentease.events`;
- вставить скрин RabbitMQ Management UI с очередью `communication.booking-confirmed`;
- вставить скрин ответа `PATCH /api/v1/bookings/{id}/status` со статусом `confirmed`;
- вставить скрин ответа `GET /api/v1/notifications` с `BOOKING_CONFIRMED`.

## ВЫВОД

В RentEase настроен RabbitMQ и реализован асинхронный обмен событиями между
Booking Service и Communication Service. Подтверждение бронирования теперь
передается через broker, обрабатывается consumer и превращается в уведомления
пользователей. Сценарий запуска и проверки описан в `БР1.1/hw5/README.md`.
