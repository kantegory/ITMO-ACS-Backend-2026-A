# ДЗ6. Автоматическое развёртывание через GitHub Actions и Ansible

В репозитории настроен workflow `.github/workflows/deploy.yml`. Отправка изменений приложения или Ansible в ветку `hw6-ci-cd` запускает проверку и развёртывание. Изменения PDF и DOCX исключены из триггера. Также доступен ручной запуск `workflow_dispatch`.

## Проверка перед развёртыванием

Задание `Validate configuration and build TypeScript` устанавливает Node.js 22, Python 3.12 и ansible-core 2.19.3, проверяет синтаксис playbook и shell-скриптов, конфигурацию Docker Compose и компилирует все шесть сервисов. При ошибке сборки деплой не запускается.

## Развёртывание через Ansible

Задание `Deploy with Ansible` создаёт SSH-конфигурацию и inventory из GitHub Secrets: `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_SSH_KEY`, `DEPLOY_KNOWN_HOSTS`. Проверка ключа сервера включена. Приватный ключ и `.env` не входят в репозиторий и архив приложения.

Playbook `labs/lab4/ansible/site.yml` настраивает пакеты и Docker, передаёт приложение, сохраняет существующий `.env`, применяет шаблон nginx и обновляет контейнеры. Использованы роли `base`, `docker`, `backend_app`, `nginx`.

После развёртывания проверяются контейнеры, конфигурация nginx, документация шести сервисов и API справочников. Runner запрашивает `/deployment.json` через публичный адрес и сравнивает SHA с коммитом workflow. Затем тот же playbook запускается повторно для проверки идемпотентности.

## Проверка обновления

Для воспроизведения проверки отправляется изменение кода приложения или Ansible в ветку `hw6-ci-cd`. Во вкладке Actions проверяются оба задания, итоговый PLAY RECAP и совпадение SHA в [метке версии](http://168.113.254.187/deployment.json). Приложение доступно по адресу http://168.113.254.187/.

Развёртывания выполняются последовательно через `concurrency`. Секреты приложения остаются на сервере. Автоматический откат не реализован. HTTPS не настроен.
