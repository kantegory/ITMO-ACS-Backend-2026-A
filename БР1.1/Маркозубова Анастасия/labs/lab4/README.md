# Практическая работа 4. Развёртывание приложения

## Цель работы

Развернуть бэкенд-приложение на удалённом сервере и настроить nginx в режиме обратного прокси для доступа к сервисам из внешней сети.

## Настройка сервера

Для размещения приложения создана виртуальная машина backend-lab4 в Cloud.ru Evolution, зона доступности ru.AZ-3. На сервере установлена Ubuntu 24.04.4 LTS. Конфигурация ВМ: 2 vCPU, 4 ГБ оперативной памяти и SSD объёмом 30 ГБ.

Серверу назначен публичный IP-адрес 168.113.254.187. В группе безопасности разрешены входящие TCP-соединения на порты 22 и 80. Для подключения использован пользователь user1 и SSH-ключ. Для выхода внутренней подсети в интернет создан SNAT-шлюз.

После подключения установлены Docker Engine и Docker Compose. Работоспособность Docker проверена запуском контейнера hello-world.

## Развёртывание приложения

Исходный код приложения загружен в каталог ~/backend-lab4. Для развёртывания использован файл compose.yaml. В нём описаны шесть сервисов приложения, отдельные базы PostgreSQL, RabbitMQ и nginx.

Сервисы, базы данных и брокер сообщений подключены к общей Docker-сети. Во внешнюю сеть опубликован только порт 80 контейнера nginx. Для хранения данных PostgreSQL и RabbitMQ созданы именованные тома. Пароли и ключ подписи токенов вынесены в файл .env.

Установка зависимостей выполнена скриптом scripts/setup-server.sh. Сборка образов и запуск контейнеров выполнены скриптом scripts/deploy.sh. После запуска проверены состояния контейнеров: все сервисы перешли в состояние healthy.

При первом запуске возникла ошибка создания очередей RabbitMQ. В используемой версии брокера временные неэксклюзивные очереди запрещены по умолчанию. Для очередей сервисов установлен параметр durable: true. После пересборки сервисы запустились успешно.

## Настройка nginx

В файле nginx/default.conf настроено перенаправление запросов по префиксам:

| Путь | Сервис |
| --- | --- |
| /auth/ | auth-service:8001 |
| /profile/ | profile-service:8002 |
| /resume/ | resume-service:8003 |
| /vacancy/ | vacancy-service:8004 |
| /application/ | application-service:8005 |
| /reference/ | reference-service:8006 |

В proxy_pass указан завершающий слеш. Поэтому nginx удаляет префикс сервиса перед передачей запроса. Например, запрос /reference/api/industries/ передаётся в reference-service по пути /api/industries/.

Главная страница содержит ссылки на документацию API всех шести сервисов. Swagger настроен на использование относительных адресов, поэтому запросы из документации также проходят через nginx.

Конфигурация проверена командой nginx -t. Получены сообщения syntax is ok и test is successful.

## Автоматизация настройки ВМ средствами Ansible

23.10.2026 настройка сервера и развёртывание приложения выполнены через Ansible. Файлы находятся в `labs/lab4/ansible`. Playbook `site.yml` применяет роли `base`, `docker`, `backend_app` и `nginx`.

Роль `base` устанавливает базовые пакеты и обеспечивает работу SSH. Роль `docker` настраивает официальный репозиторий, устанавливает Docker Engine и Compose, включает автозапуск Docker. Роль `backend_app` передаёт приложение, сохраняет существующий `.env` с правами 0600 и запускает развёртывание при изменениях. Роль `nginx` формирует конфигурацию обратного прокси из Jinja2-шаблона.

Обработчик развёртывания запускает сборку, ожидает готовности контейнеров и пересоздаёт nginx. Успешный релиз отмечается файлом `.ansible-deployed-sha`; незавершённый релиз повторяется при следующем запуске. Проверка контрольной суммы подтвердила сохранение существующего `.env`.

Для проверки выполнены два запуска одного playbook с одинаковыми архивом и SHA. При повторном запуске получен результат:

```text
cloudru                    : ok=31   changed=0    unreachable=0    failed=0    skipped=1    rescued=0    ignored=0
```

Все 14 контейнеров работают. Документация шести сервисов отвечает HTTP 200. Запрос к справочнику отраслей вернул 10 записей. Учебные данные сохранились: доступны 2 компании, 4 вакансии и 2 резюме.

SHA в [deployment.json](http://168.113.254.187/deployment.json) совпал с коммитом запуска. [Проверенный запуск Ansible](https://github.com/mmmilkinnn/ITMO-ACS-Backend-2026-A/actions/runs/39963222282).

Ansible выполнен на Linux runner GitHub Actions. Windows используется для работы с исходниками и SSH; Ansible непосредственно в Windows не запускался. Проверена настройка существующей ВМ. Развёртывание на новой пустой ВМ отдельно не проводилось.
