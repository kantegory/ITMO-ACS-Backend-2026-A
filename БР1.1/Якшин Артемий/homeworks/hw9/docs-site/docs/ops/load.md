# Нагрузка и SLO

Сценарии нагрузочного тестирования (k6) лежат в `homeworks/hw10/k6`, подробная методика — в отчёте ДЗ10, испытания и автоскейлинг — в ЛР8.

## SLO

| SLI | SLO | Как измеряется |
|---|---|---|
| Доступность (доля ответов без 5xx) | ≥ 99.5 % за 30 дней | `http_requests_total{app="gateway"}` |
| Задержка чтения p95 / p99 | < 300 / 700 мс | `http_request_duration_seconds` gateway |
| Задержка записи (бронь) p95 | < 500 мс | то же, `route=~".*reservations.*"` |
| Вход p95 | < 600 мс | `route="/api/v1/auth/login"` |
| Пропускная способность | ≥ 50 запросов/с без нарушения SLO | профиль `load` |

SLA для пользователей — 99 % доступности и p95 < 1 с; разница с SLO образует бюджет ошибок.

## Профили k6

```bash
cd homeworks/hw10/k6
k6 run -e BASE_URL=http://<SERVER_IP>:8088/k8s -e PROFILE=<smoke|load|stress|spike|soak|hpa> [-e RATE=1.5] scenarios.js
```

| Профиль | Форма | Длительность |
|---|---|---|
| smoke | 1 VU, полный путь пользователя | < 1 мин |
| load | ~50 запросов/с (чтение 45/с, вход 2/с, бронь 1/с) | 5 мин |
| stress | чтение ступенями до 200/с, вход до 6/с | 8 мин |
| spike | 30 → 180 → 30 запросов/с за 10 с | 4.5 мин |
| soak | 30 + 1 + 1 в секунду | 10 мин |
| hpa | вход до 8/с, чтение до 60/с (× `RATE`) | 6.5 мин |

## Результаты (облачный стенд)

| Прогон | Поток | Сервер: p95 / p99 gateway | Ошибки |
|---|---|---|---|
| load | 49 запросов/с | 28 / 91 мс | 0 % |
| stress, пик | ~184 запроса/с | 71 / 160 мс | 0 % |

Узкое место — вход (bcrypt, ~40–50 мс CPU на запрос): одна реплика auth с лимитом 500m насыщается на ~10–12 входах в секунду. Решение — HPA и пересмотр лимитов (ЛР8).
