# 06. Разбор ДЗ7: технический дизайн облачной инфраструктуры

## Что ожидается в результате

ДЗ7 — документ, в котором спроектированная вами инфраструктура описана так, что по ней можно работать: другой инженер сможет развернуть окружение, а на защите вы сможете объяснить каждое решение. Четыре обязательных блока задания — архитектурные решения, облачные ресурсы, сетевая связность, отказоустойчивость; файлы 01-05 темы покрывают каждый из них.

По изначальному сроку ДЗ7 идёт 21.11.2026, за ним ЛР7 (05.12.2026) — развёртывание ровно того, что вы здесь спроектируете. Относитесь к документу как к рабочему артефакту, а не отчётной формальности: кривой дизайн означает сложности в ЛР7.

## Структура отчёта

По шаблону курса, содержательная часть — примерно такая:

1. **Описание приложения.** Ваши микросервисы из ДЗ4/ЛР3, зависимости между ними, какая БД у каждого сервиса, где очередь. Один-два абзаца + схема вызовов.
2. **Модель размещения.** Managed Kubernetes — основная линия курса; если для вашего проекта выбираете что-то другое, обоснование требуется вдвое тщательнее.
3. **Карта ресурсов.** Для каждого сервиса приложения — чем он обеспечен: тип инстанса или пода, конфигурация managed-БД, брокер сообщений, объектное хранилище, реестр. Здесь уместна таблица «сущность приложения → облачный ресурс».
4. **Сетевая топология.** VPC, подсети по зонам, какие ресурсы где живут и почему, путь трафика от пользователя до последнего сервиса, security groups. Схема обязательна.
5. **Отказоустойчивость.** Сценарии отказов (упала нода, отказала зона, удалена таблица), что происходит в каждом, цифры RTO/RPO, как это обеспечивается конфигурацией из блоков 2-4.
6. **План развёртывания.** Порядок создания ресурсов (сеть → БД → реестр → кластер → балансировщик → DNS), хотя бы в виде последовательности шагов; идеальный вариант — скелет Terraform.
