# 09. Разбор ЛР7: облачное развёртывание веб-приложения

## Что требует задание

ЛР7 (срок 05.12.2026): настроить облачное развёртывание и оркестрацию для микросервисного веб-приложения в облачной инфраструктуре (Kubernetes / Managed Cloud Services) согласно техническому дизайну из ДЗ7. Результат — работающее приложение в облаке + отчёт.

Ключевое слово здесь «согласно ДЗ7». Задание оценивает не столько факт поднятия pod'ов, сколько способность довести спроектированное до реализованного: если в дизайне был отказоустойчивый кластер из трёх зон, а в реальности — один базовый кластер в одной зоне, это должно быть объяснено в отчёте (например, бюджетом).

## Рабочий путь

1. **Проверить соответствие дизайна и возможностей** до начала развёртывания: список ресурсов ДЗ7 и их доступность у выбранного провайдера, актуальные цены, квоты аккаунта. Если дизайн не сходится с бюджетом — фиксировать правки в документе, ДЗ7 не догма.
2. **Развернуть инфраструктуру.** По возможности Terraform — тогда пункт «план развёртывания» отчёта подтверждается кодом в репозитории.
3. **Подготовить сервисы**: каждый микросервис из ЛР2 получает Dockerfile из ЛР3 (перепроверить, что образ собирается без изменений), манифест из файла 02 (Deployment + Service + probe'ы, requests/limits из файла 05), конфигурацию из файла 03 (ConfigMap манифестом, секреты через CLI).
4. **Выпустить наружу**: Ingress + сертификат + DNS (сертификат и DNS при наличии домена), приложение открывается по домену — это момент, когда работа становится полностью готовой.
5. **Подтвердить отказоустойчивость** поведенчески: удалить pod руками (кластер восстановил), сделать rollout undo (откат работает), если бюджет позволяет — drain ноды (PDB не уронил сервис). Каждый пункт — скриншот или лог в отчёт.
6. **Мониторинг**: Grafana из темы 3.4 смотрит на новый кластер вместо ВМ — либо перенести node_exporter/Loki, либо подключить Managed Service for Prometheus. Пункт «логи со всех контейнеров» должен работать и в новой топологии.
7. **Собрать отчёт** по шаблону.

## Отчёт

Содержательные части: схема развёрнутой инфраструктуры (обновлённая относительно ДЗ7), список манифестов с ключевыми полями, скриншоты живого приложения по домену/IP и результатов поведенческих проверок из шага 5, расхождение дизайна и факта с обоснованием. На защите приготовьте `kubectl get all -n <namespace>` и демонстрацию: удалить pod, показать восстановление; откатить версию, показать смену поведения (или запишите такую демонстрацию на видео заранее, чтобы можно было его включить и прокомментировать).
