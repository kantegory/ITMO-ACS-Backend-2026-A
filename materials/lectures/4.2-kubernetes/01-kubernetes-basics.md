# 01. Зачем нужен оркестратор и как устроен кластер

## Проблема, которую решает Kubernetes

В ЛР3 приложение запускалось командой `docker compose up`: несколько контейнеров, общая сеть (или несколько), volumes, healthcheck-и. Для одного хоста этого вполне достаточно. Как только хостов становится больше, появляются новые вопросы: где именно запускать контейнер, чтобы не перегрузить одну машину, как доставить образ на нужный хост, что делать, когда контейнер завершился, а кто-то уже успел послать ему запрос, как обновить сервис без простоя и как откатиться, если возникает такая потребность. Безусловно, эти задачи можно решить и с docker compose, но Kubernetes решает их декларативно: вы описываете желаемое состояние в YAML, а кластер сам его поддерживает.

Зафиксируем положение: Kubernetes — это контроллер, который непрерывно сравнивает описанное вами состояние с фактическим и чинит расхождения. Запустили деплоймент с репликами 3 — он создаст три пода. Один упал — он создаст четвёртый вместо него до восстановления третьего. Удалили деплоймент — он выключит всё, что тот создал. Отсюда и термин «оркестрация контейнеров».

## Control plane и worker-ноды

Кластер делится на две части. **Control plane** — это API-сервер (единственная точка входа: все команды проходят через него, `kubectl` просто ходит в его HTTP API), планировщик (решает, на какую ноду поместить под), контроллеры (те самые ревизоры желаемого и фактического состояния) и хранилище etcd, где живёт само описание состояния.

**Worker-ноды** — машины, на которых containers и работают. На каждой ноде крутится kubelet (агент, исполняющий решения control plane на своей машине) и container runtime. Сетевой слой (kube-proxy и CNI-плагины) обеспечивает связность подов между нодами.

В managed-исполнении (Yandex Managed Service for Kubernetes, Selectel Managed Kubernetes, EKS) control plane — забота провайдера: его master-ноды скрыты от вас, обновляются им же, переживают отказ зоны (в отказоустойчивом типе кластера — три мастера в разных зонах). Ваша задача — группа нод: тип и количество worker-машин, их обновление и масштабирование. Разница в цене кластера «базовый/отказоустойчивый» у провайдеров — это как раз про отказоустойчивость master-узлов: для учебного проекта берётся базовый, в продакшене он не выдерживает отказ зоны.

## YAML как основной язык

Практически всё взаимодействие с Kubernetes — это манифесты: YAML-документы, описывающие ресурсы. Структура у всех ресурсов общая:

```yaml
apiVersion: apps/v1        # версия API группы ресурсов
kind: Deployment            # тип ресурса
metadata:
  name: orders-service      # имя и лейблы
  labels:
    app: orders
spec:                       # желаемое состояние — то, что описываете вы
  replicas: 2
  template:
    spec:
      containers:
        - name: orders
          image: cr.yandex/.../orders:v1
status:                     # фактическое состояние — пишет кластер
  readyReplicas: 2
```

Слева от вас всегда `spec`, справа от кластера — `status`. Команда `kubectl get deploy orders -o yaml` показывает полный документ, `kubectl describe` — удобную сводку с событиями, а события — первое место, куда следует обратить своё внимание при разборе, почему под не стартует.

Поле `apiVersion` отражает стабильность API: `v1` — ядро (Pod, Service, ConfigMap), `apps/v1` — рабочие нагрузки, `networking.k8s.io/v1` — Ingress. Старые версии из статей 2019 года (`extensions/v1beta1`) в актуальных кластерах уже не работают, при изучении чужих примеров обращайте внимание на актуальность предоставляемой информации.

## Чем Kubernetes точно не является

Это не docker и не docker compose. Контейнеры запускает container runtime на нодах, Kubernetes ими только управляет; собрать образ по-прежнему нужно самим (ЛР3). Это не PaaS: приложение всё ещё ваши Dockerfile, а не «выложили код — платформа разобралась», в этом смысле вы остаётесь на уровне CaaS из темы 4.1, и только Managed Kubernetes приближает вас к PaaS, беря эксплуатацию control plane на провайдера. И это не система конфигурации: установка Node.js внутри образа — забота Dockerfile и Ansible, а не манифестов деплоя.
